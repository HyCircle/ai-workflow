# failure-modes —— 机制已知失效模式(留作纪律)

> **这是什么**:本机制历次翻车的蒸馏登记册。每条 = 症状 → 根因 → 现行规则(+ 在哪强制)。
> 改 `wf/` 代码前先扫一遍:别把已经填过的坑重新踩一遍。
>
> **面向谁**:维护者。**不投影进消费项目** —— 消费者面向的常驻纪律是 `discipline.md`,那份不带这里的维护教训。
>
> **和纪律⑥(刻疤清理)的关系**:纪律⑥ 禁的是**代码/文档里的疤痕注释**。一份专门的复盘登记册是前瞻规则,
> 写这里、别写进代码。原始证据见 `docs/history/`。

---

## FM-1 · 改动清单从 `git status` 文本截取 —— 解析错改名与特殊文件名

- **症状**:worker 改动含改名,或文件名第三个字符是空格时,从 porcelain 文本按位置截取路径会解析错,越界判定失真。
- **规则**:路径清单走 git 的纯路径输出:`git diff --name-only --no-renames -z HEAD` + `git ls-files --others --exclude-standard -z`。
- **在哪强制**:`wf/dispatch.py` 的 `_protected_state`;`tests/test_wf.py` 用带空格的文件名覆盖。

## FM-2 · 越界检查把派单前已有的改动算到 worker 头上

- **症状**:负责人刚写完 ADR 未提交就派单,越界检查按「当前工作树相对 HEAD」判定,把负责人自己的改动报成 worker 越界。
- **规则**:越界 = worker 前后受保护文件内容的变化,派单前已有的改动不计入。
- **在哪强制**:`wf/dispatch.py` 的 `Run.work`;`tests/test_wf.py` 的派单前改动用例。

## FM-3 · 独立台账文件(dispositions.md / handoff.md)是多余机制

- **症状**:为「裁决记录」「交棒」各建一个 md 台账,与 git 和会话归档双重记账、易漂移。
- **规则**:**裁决/驳回的理由随 commit message 落库**;**交棒在 finishing 的回复与会话归档里**。不建独立台账。
- **在哪强制**:`docs/design.md` 的文档职责、`planner/SKILL.md`、`finishing/SKILL.md`。

## FM-4 · worker 自述与机器检查混为一谈

- **症状**:worker 报告里带自测结果,与 `wf` 亲跑的测试重复、且可被 worker 粉饰。
- **规则**:测试由 `wf` 亲跑并单独报告;worker 报告给出结果与证据、重要偏离、矛盾与待定,作为待核实证据回传。未运行的检查在汇总里明确写出,不把只施工的 run 标成通过。
- **在哪强制**:`planner/worker-preamble.md`、`wf/dispatch.py` 汇总。

## FM-5 · 测试全文灌进汇总 —— 淹没信号

- **规则**:汇总只给通过与否;失败时附输出最后 30 行,全文留 `test.log`。
- **在哪强制**:`wf/dispatch.py` 的 `Run.test`。

## FM-6 · 非 git 环境静默兜底 —— 定位漂到错仓

- **症状**:仓根在非 git 目录下静默回退到当前目录或脚本所在目录,错误延后爆发。
- **规则**:**非 git 直接报错退出**;仓根一律取 git toplevel,不用 `__file__` 相对定位(包装在 uv 工具目录里,与项目无关)。
- **在哪强制**:`wf/cli.py` 的 `_root`。

## FM-7 · 同一秒内两次运行的产物目录撞车

- **症状**:运行目录只按秒级时间戳命名,负责人并行启动两个审查时第二个报错退出。
- **规则**:运行目录用时间戳前缀加随机后缀,由 `tempfile.mkdtemp` 保证唯一。
- **在哪强制**:`wf/dispatch.py` 的 `Run.__init__`;`tests/test_wf.py` 连续两次运行用例。

## FM-8 · 代码/文档里的「疤痕叙述」(纪律⑥)

- **症状**:注释写成「不再手搓 X——那套有 Y 竞态」这类记录旧伤的负面叙述,或情绪化旁注。
- **规则**:删疤痕注释,改**正面陈述当前契约**。历史教训写进**本文件**,不写进代码。
- **在哪强制**:新代码 review 时照此把关。

## 有意保留的能力

- cursor / codex / claude **三后端**:跨厂异构的第二双眼,也让 worker 可选 Claude 家模型。
- 方案审(`wf ask` + `wo-review-preamble.md`)与第二审(换模型再跑 `wf review`)保留为显式可选能力,只在错误代价高或用户要求时启用。
- `.git/info/exclude` 的 `/.cursor/` `/.agents/` 忽略项。
