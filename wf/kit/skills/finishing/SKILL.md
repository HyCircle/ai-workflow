# Finishing

先读 discipline，全程中文。你是本轮的亲历者，手上有最完整的上下文；本技能把它落成一份归档、一次 TODO 更新和一段交棒。

## 1. 写归档

路径：`.workflow/scratchpad/_archive/NN-YYYYMMDD-<英文短描述>.md`。`NN` 取目录中现有最大序号 +1(两位；目录不存在时创建并从 `01` 开始)，日期用今天。

首行写来源：

```
> 来源：<backend> 会话 <完整 session UUID> · 分支 <branch> @ <HEAD 短哈希>，工作区<干净|有未提交改动> · 亲历者总结，事实以仓内证据为准
```

正文按信息量决定篇幅，包含：

- **任务**：用户要什么。
- **用户原话**：硬约束、纠正、拍板和否定，加引号原句引用，不转述。
- **决定与依据**：做了哪些选择、为什么。中途改变的判断写清原判断、使它改变的证据和新结论。
- **结论**：分开写「已验证」与「未验证 / 仅完成实现或检查」。已验证的每条附证据位置(文件、命令、数据)；结论强度不超过证据。实验类结论注明是否经 `/challenge` 结算。
- **改动**：关键路径；拟议或已用的提交消息全文，注明是否已提交。
- **未完成**：待办、原因与定位指针。
- **去处**：第 2 节分出的手册候选、协作约定候选、文档补充与 ADR 事项；没有就写无。
- **交棒**：下一步与开场提示词，与回复中的一致。

工具流水账、重复论证和被取代的中间过程不写。会话被宿主压缩过时，前段按你现有的记忆写，不补猜。

## 2. 本轮学到的东西放哪

先分去处，再决定要不要写：

- **长期设计** → 标出来，交 bs / planner 写进 ADR。
- **环境、接口、数据等项目事实** → 写明该补进哪份项目文档。
- **有时效的事**(等答复、某次运行的数字、暂时绕开的问题) → TODO。
- **用户对所有 agent 都适用的要求**(交流方式、提交规范) → AGENTS「协作约定」的候选。
- **关于工作流本身的意见** → 在回复里单独告诉用户。
- **同类任务的做法与坑** → 手册候选。

手册候选默认没有，每轮最多两条。只有同时满足四条才列：

1. 这类任务以后还会做；
2. 不会随时间失效；
3. discipline、AGENTS、手册、项目文档和提示词里都还没写；
4. 不写它，下次大概率会做错，而不只是这次踩过。

每条一两句，正面写做法，注明适用的任务类型和本轮的依据。cleaning 复核后交用户确认再合入；用户当场要求时直接写进对应手册。

## 3. 更新 TODO

按 AGENTS 里 TODO 的格式改与本轮相关的条目：完成且有落地证据的删除；状态变了的整条重写；新的下一步、等别人的事和已知问题各写一条。细节、数字和过程放进归档或项目文档，TODO 只留指针。

## 4. 交棒回复

在回复里简短说明：

- 本轮结果与验证范围(区分实现完成、检查通过、真实结果已验证)；
- 未完成项及其定位指针；
- 第 2 节分出的事项(若有)；
- 归档路径；
- 可复制的「下 session 开场提示词」。

文档巡检与手册合并攒几轮后用 `/cleaning`。
