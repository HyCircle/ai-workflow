# Cleaning

先读 discipline 和 AGENTS，命令取自 workflow.env，全程中文。你是没参与近期施工的冷读者：近期归档告诉你最近改了什么，仓库实况告诉你累积了什么。归档是待核实的历史记录，本轮操作依据当前用户授权。

顺序：读近期归档 → 合入手册 → 全仓巡检 → 处置 → scratch 清理 → 汇报。

## 范围与写入权

- **巡检范围** = AGENTS 声明的写文件边界（如「仅 `eval/` + 工作流文件」）；未声明时为整仓受版本管理的文件加 `.workflow/`。边界外只读。
- **直接写**：工作流文档（architecture、TODO、patterns、AGENTS 文档路由）、边界内文档的事实性修正、scratch。
- **候选清单**：受版本管理文件的删除或搬迁、判断型改写、价值不确定的 scratch，见「处置」。
- **交出**：代码与测试的实质修改写进 TODO 交 planner；ADR 由 bs / planner 著作，成为长期规则的新教训标给他们；ADR 之间的冲突、重叠或多余复杂度建议用户跑 `/holistic`。

## 1. 读近期归档

`.workflow/scratchpad/_archive/.last-cleaning` 记录上次处理到的归档序号。读其后的全部归档；文件不存在时读最近 5 份，并问用户是否需要更早的。结束时把它更新为本次处理到的最大序号。

## 2. 合入手册

逐条处理归档里的「手册候选」：先对照代码与实况确认仍成立，再按任务类型合入 `.workflow/patterns/<任务类型英文短名>.md`。同类条目合并；与已有条目冲突时以实况为准改写。新建手册用以下格式，没有内容的节省略：

```
# <任务类型>

适用：<什么任务该读这份>

## 步骤
## 坑
## 验证清单
```

每条一两句，正面写做法（discipline ⑥）。新增与合并直接做；删除或改变已有条目含义的改写进候选清单。条目已被代码、测试或 ADR 更好地承载时，列入候选删除。

## 3. 全仓巡检

先用 `git ls-files` 加 `.workflow/` 列出范围内的文件清单，按目录过一遍；深读集中在近期归档涉及的改动和扫出信号的地方。范围大时按目录分批，汇报写明覆盖范围。

1. **近期落地核验**：归档里改动、新增、删除的模块与契约，逐项对照代码确认落地；相关文档和 TODO 是否跟上。
2. **文档与实况**：README、docs、AGENTS、architecture、patterns 中的命令、路径、文件名、配置名、常量和接口描述，用 grep、`ls`、`--help` 或读代码核对仍然成立；`ADR-NNNN` 引用指向存在的文件。
3. **死物**：没有消费者的脚本、测试、配置、数据和文档（grep 引用与 import 确认）；只为一次性迁移存在的兼容层；残留的临时文件与空目录。
4. **重复与疤痕**：同一事实散在多处，收归一处并让其他处引用；防御性括注、事故叙述按 discipline ⑥ 蒸馏成正面表述。
5. **慢层文档**：architecture 只装当前设计现状（模块边界、数据模型、关键不变量、对外契约、已能用的功能），具体决定引用 `ADR-NNNN`，冲突时 ADR 赢；进度看板、重定向空壳、逐字复述 ADR 的段落列入候选。TODO 保持扁平，装下一步、未完成项与已知问题，移除有落地证据的完成项。
6. **ADR 全局信号**：同一主题多份 ADR、ADR 之间或与代码说法冲突，列进汇报并建议 `/holistic`；本技能不改 ADR 正文。
7. **scratch 产物**：会话目录、`runs/` 及其余散落产物（探针目录、笔记），按 TODO / ADR / architecture 是否仍引用判断去留，见第 5 节。

## 4. 处置

**路径 A——直接做**：可逆且有实况依据的修正。文档中与实况不符的命令、路径、名称、状态；已完成的 TODO；断链；手册的新增与合并；第 5 节的 scratch 清理。汇报逐条列出。

**路径 B——候选清单，用户确认后执行**：受版本管理文件的删除或搬迁、跨文件合并蒸馏、改变文档承载含义的判断型改写（含 architecture 叙述重组与手册条目删改）、价值不确定的 scratch。清单每行写【路径 + 理由 + 依据 + 风险】；用户勾选后在本 session 执行，未勾选的保持原样。

**风险分层**（从高到低）：

1. **永久保护**：带 `NO-GO`、`别翻案`、`已验证净负`、`留档不删`、`别重做` 标记的内容一律保留。
2. **探针随决策存活**：可复跑的实验脚本连同结论随其 ADR 存续；ADR 删除或整体过时时，连同结论进候选清单。红队、方案文稿属于 scratch，随目录清理。
3. **引用成簇处理**：删除被 import 或被引用的文件前先 grep 全部引用方，连簇一起进清单。
4. **蒸馏只压表达**：数据形状、硬上限、判据措辞照抄；带 `ADR-NNNN` 锚点的说法保留。吃不准是否承重就进候选清单。

真两难归用户。

## 5. Scratch 清理

- **会话目录** `PL-`/`BS-`/`HO-<UUID>/`：UUID 已出现在 `_archive/` 中且内容不再被引用的，直接删除；没有对应归档的列入候选。仍被引用的材料进候选清单，或搬到它该在的家。
- **`runs/`**：带 `.done` 的按时间保留最近 10 个，其余删除；仍被任务或证据引用的另行保留；失败或中断（无 `.done`）的列入候选。
- **其余产物**：说明内容与引用情况后进候选清单。
- 删除使用核实过的 scratchpad 内精确路径，保留软链目标；`_archive/` 不动。

## 6. 收尾

自检：

- 近期碰过的常量、配置名、路径，文档说法与代码一致？
- 新事实各归其家：现状 → architecture，下一步与已知问题 → TODO，同类任务的做法与坑 → patterns，长期规则 → 标给 bs / planner 写 ADR；同一事实只在一处。
- 受版本管理文件的删除、搬迁均经用户确认，ADR 正文未改动？
- `.last-cleaning` 已更新？

汇报：

- 处理的归档范围；
- 合入或新建的手册；
- 巡检覆盖范围（扫过的目录，未扫部分及原因）；
- 路径 A 已做的改动；
- 路径 B 候选清单及处理结果；
- 交给 planner / bs 的事项，及是否建议 `/holistic`；
- 已删除的目录。
