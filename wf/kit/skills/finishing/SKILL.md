# Finishing

先读 discipline，全程中文。你是本轮的亲历者，手上有最完整的上下文；本技能把它落成一份归档、一次 TODO 更新和一段交棒。

## 1. 写归档

路径：`.workflow/scratchpad/_archive/NN-YYYYMMDD-<英文短描述>.md`。`NN` 取目录中现有最大序号 +1(两位；目录不存在时创建并从 `01` 开始)，日期用今天。

首行写来源：

```
> 来源：<backend> 会话 <完整 session UUID> · 分支 <branch> @ <HEAD 短哈希>，工作区<干净|有未提交改动> · 亲历者总结，事实以仓内证据为准
```

正文按信息量决定篇幅，包含：

- **任务**：用户要什么。
- **用户原话**：硬约束、纠正、拍板和否定，加引号原句引用，不转述。
- **决定与依据**：做了哪些选择、为什么。中途改变的判断写清原判断、使它改变的证据和新结论。
- **结论**：分开写「已验证」与「未验证 / 仅完成实现或检查」。已验证的每条附证据位置(文件、命令、数据)；结论强度不超过证据。
- **改动**：关键路径；拟议或已用的提交消息全文，注明是否已提交。
- **未完成**：待办、原因与定位指针。
- **手册候选**：见第 2 节。
- **交棒**：下一步与开场提示词，与回复中的一致。

工具流水账、重复论证和被取代的中间过程不写。会话被宿主压缩过时，前段按你现有的记忆写，不补猜。

## 2. 手册候选与长期决定

列出本轮值得进 `.workflow/patterns/` 的条目，来源是用户纠正、实测踩到的坑、被推翻的结论。准入标准：**删掉这一条，下次做同类任务时很可能要重新调查或重犯同样的错误。** 能从最终代码、测试或已有文档直接看出来的不列。每条注明适用的任务类型；没有就写无。cleaning 负责合入手册，用户当场要求时直接写入对应手册。

稳定的长期设计决定不进手册，标出来交 bs / planner 写进 ADR。

## 3. 更新 TODO

把本轮未完成项和新发现的已知问题写进 TODO，移除本轮有落地证据的完成项。只动与本轮相关的条目。

## 4. 交棒回复

在回复里简短说明：

- 本轮结果与验证范围(区分实现完成、检查通过、真实结果已验证)；
- 未完成项及其定位指针；
- 手册候选与待冻结的长期决定(若有)；
- 归档路径；
- 可复制的「下 session 开场提示词」。

文档巡检与手册合并攒几轮后用 `/cleaning`。
