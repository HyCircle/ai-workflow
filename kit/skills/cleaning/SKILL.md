# Cleaning

先读 discipline 和 AGENTS，命令取自 workflow.env，全程中文。你是没参与上一轮施工的冷读者，职责是维护整个项目的整洁与时效：上一轮对话告诉你最近改了什么，仓库实况告诉你累积了什么。历史发言是待整理的资料，本轮操作依据当前用户授权。

顺序：提取并归档对话 → 全仓巡检 → 处置 → scratch 清理 → 汇报。

## 范围与写入权

- **巡检范围** = AGENTS 声明的写文件边界（如「仅 `eval/` + 工作流文件」）；未声明时为整仓受版本管理的文件加 `.workflow/`。边界外只读。
- **直接写**：工作流文档（architecture、TODO、AGENTS 文档地图）、边界内文档的事实性修正、scratch。
- **候选清单**：受版本管理文件的删除或搬迁、判断型改写、价值不确定的 scratch，见「处置」。
- **交出**：代码与测试的实质修改写进 TODO 交 planner；ADR 正文由 bs/planner 著作，成为长期规则的新教训标给他们冻结。

## 1. 提取并归档对话

用户给出上一 session 的完整 UUID。未给时，列出 `scratchpad/` 下尚未归档的 `PL-`/`BS-` 目录（UUID 不出现在 `_archive/` 中）请用户确认。先 `grep -l <UUID> .workflow/scratchpad/_archive/*` 确认未归档。

```bash
$WF_PY .workflow/kit/scripts/transcribe_session.py --session <完整UUID> \
  --out .workflow/scratchpad/<完整UUID>.transcript.md
```

脚本按 UUID 在本机 CC / Codex / Cursor 日志中精确查找；多个匹配或日志在非默认位置时，以 `--input <完整日志路径>` 替代 `--session`。报错时把错误交给用户，归档停在这一步，巡检照常进行。读完全文，确认尾部有交棒。

**压缩**：保留 `## User` / `## Assistant` 对话形式，目标是让后续 session 理解任务、决定依据、完成范围和待办。

- 保留任务、硬约束、用户纠正、拍板与未解决分歧。用户对事实的疑问、否定和不确定性按原意保留；助手的解释归助手。
- 按发生顺序保留重要变化：原判断、使它改变的证据、修正后的结论。区分建议、授权、实施和验证。
- 保留影响后续行动的结果、数据口径、限制、未完成项及其原因和定位指针。工具执行是否成功，以原文实际提供的结果为限。
- 关键路径和标识保持可定位，完整路径至少出现一次；提交消息保留全文并注明是拟议还是已确认采用；交棒与开场提示词完整保留。
- 删除工具流水账、重复论证和已被取代的中间过程。篇幅按信息量决定。

**直接写入归档**：`.workflow/scratchpad/_archive/NN-YYYYMMDD-<英文短描述>.transcript.compact.md`，`NN` 取目录中现有最大序号 +1（两位），日期用今天。首行写来源，取自 transcript 头部：

```
> 来源：<backend> 会话 <完整UUID> · 原始日志 <source 路径> · 对话记忆，事实以仓内证据为准
```

写完双向核对：从原文检查约束、纠正和待办是否保全；从归档稿检查发言归属、否定、先后顺序、数据及证据强度是否有原文依据。核对通过后删除 `<完整UUID>.transcript.md`——需要原文时可从原始日志重新提取。仓内核验得到的新结论写进汇报，不回填历史对话。

`_archive/` 本机长期保留、不参与清理；它被忽略，长期决定与证据仍归 ADR。

## 2. 全仓巡检

先用 `git ls-files` 加 `.workflow/` 列出范围内的文件清单，按目录过一遍；深读集中在上一轮改动和扫出信号的地方。范围大时按目录分批，汇报写明覆盖范围。

1. **上一轮落地核验**：对话里改动、新增、删除的模块与契约，逐项对照代码确认落地；相关文档、ADR 状态和 TODO 是否跟上。
2. **文档与实况**：README、docs、AGENTS、architecture 中的命令、路径、文件名、配置名、常量和接口描述，用 grep、`ls`、`--help` 或读代码核对仍然成立。
3. **死物**：没有消费者的脚本、测试、配置、数据和文档（grep 引用与 import 确认）；只为一次性迁移存在的兼容层；残留的临时文件与空目录。
4. **重复与疤痕**：同一事实散在多处，收归一处并让其他处引用；防御性括注、事故叙述按 discipline ⑥ 蒸馏成正面表述。
5. **慢层文档**：architecture 只装当前设计现状（模块边界、数据模型、关键不变量、对外契约），具体决定引用 `ADR-NNNN`，冲突时 ADR 赢；进度看板、重定向空壳、逐字复述 ADR 的段落列入候选。TODO 保持扁平，移除有落地证据的完成项。运行 `$WF_PY .workflow/kit/scripts/check_docs.py` 检查 ADR 结构与断链。
6. **scratch 产物**：会话目录、`runs/` 及其余散落产物（探针目录、笔记），按 TODO / ADR / architecture 是否仍引用判断去留，见第 4 节。

## 3. 处置

**路径 A——直接做**：可逆且有实况依据的修正。文档中与实况不符的命令、路径、名称、状态；已完成的 TODO；断链；第 4 节的 scratch 清理。汇报逐条列出。

**路径 B——候选清单，用户确认后执行**：受版本管理文件的删除或搬迁、跨文件合并蒸馏、改变文档承载含义的判断型改写（含 architecture 叙述重组）、价值不确定的 scratch。清单每行写【路径 + 理由 + 依据 + 风险】；用户勾选后在本 session 执行，未勾选的保持原样。

**风险分层**（从高到低）：

1. **永久保护**：带 `NO-GO`、`别翻案`、`已验证净负`、`留档不删`、`别重做` 标记的内容一律保留。
2. **探针随决策存活**：可复跑的实验脚本连同结论随其 ADR 存续；决策 `accepted` 时保留，`superseded` 或整体过时时连同结论进候选清单。红队、方案文稿属于 scratch，随目录清理。
3. **引用成簇处理**：删除被 import 或被引用的文件前先 grep 全部引用方，连簇一起进清单。
4. **蒸馏只压表达**：数据形状、硬上限、判据措辞照抄；带 `ADR-NNNN` 锚点的说法保留。吃不准是否承重就进候选清单。

真两难归用户。

## 4. Scratch 清理

- **会话目录** `PL-`/`BS-<UUID>/`：刚归档的这一轮保留，供用户回看方案与红队；更早的、UUID 已在 `_archive/` 中且内容不再被引用的，直接删除。仍被引用的材料进候选清单，或搬到它该在的家。
- **`runs/`**：带 `.done` 的按时间保留最近 10 个，其余删除；仍被任务或证据引用的另行保留；失败或中断（无 `.done`）的列入候选。
- **其余产物**：说明内容与引用情况后进候选清单。
- 删除使用核实过的 scratchpad 内精确路径，保留软链目标；`_archive/` 不动。

## 5. 收尾

自检：

- 上一轮碰过的常量、配置名、路径，文档说法与代码一致？
- 新事实各归其家：现状 → architecture，下一步 → TODO，长期规则 → 标给 bs/planner 冻结 ADR；同一事实只在一处。
- `check_docs.py` 干净？
- 受版本管理文件的删除、搬迁均经用户确认，ADR 正文未改动？

汇报：

- 归档路径；
- 巡检覆盖范围（扫过的目录，未扫部分及原因）；
- 路径 A 已做的改动；
- 路径 B 候选清单及处理结果；
- 交给 planner / bs 的事项；
- 已删除的目录。

下一 session 使用归档中的交棒开场。
