# Cleaning

先读 discipline 和 AGENTS，命令取自 workflow.env，全程中文。你是没参与近期施工的冷读者：近期归档告诉你最近改了什么，仓库实况告诉你累积了什么。归档是待核实的历史记录，本轮操作依据当前用户授权。

顺序：读近期归档 → 筛手册候选 → 知识层巡检 → TODO → 全仓巡检 → scratch 与归档 → 汇报。第 2、3、4 节和其余判断项汇总成一份清单交用户，确认后在本 session 执行。

## 范围与写入权

- **巡检范围** = AGENTS 声明的写文件边界(如「仅 `eval/` + 工作流文件」)；未声明时为整仓受版本管理的文件加 `.workflow/`。边界外只读。
- **直接做**：可逆且有实况依据的修正——文档中与实况不符的命令、路径、名称；断链；有落地证据的已完成 TODO；第 6 节中规则明确的 scratch 清理。汇报逐条列出。
- **交用户确认**：手册与协作约定的增删改、私有记忆的迁移与删除、TODO 的压缩与删除、受版本管理文件的删除或搬迁、判断型改写(含 architecture 叙述重组)、价值不确定的 scratch 与旧归档。清单每行写【对象 + 建议 + 理由 + 依据】。
- **交出**：代码与测试的实质修改写进 TODO 交 planner；ADR 由 bs / planner 著作；ADR 之间的冲突、重叠或多余复杂度建议用户跑 `/holistic`。

## 1. 读近期归档

`.workflow/scratchpad/_archive/.last-cleaning` 记录上次处理到的归档序号。读其后的全部归档；文件不存在时读最近 5 份，并问用户是否需要更早的。结束时把它更新为本次处理到的最大序号。

## 2. 筛手册候选

归档的「去处」一节列着手册候选和其他事项。对每条手册候选：

1. 对照代码与实况确认仍然成立；
2. 按 finishing 第 2 节的四条重新判断，宁缺毋滥；
3. 不该进手册的，写明它的去处(项目文档、TODO、协作约定)或直接放弃。

入选的写明合入哪份手册、合并后的措辞。确认后按任务类型合入 `.workflow/patterns/<任务类型英文短名>.md`，同类条目合并，冲突以实况为准。新建手册用以下格式，没有内容的节省略，并在 AGENTS「手册」一节加一行：

```
# <任务类型>

适用：<什么任务该读这份>

## 步骤
## 坑
## 验证清单
```

每条一两句，正面写做法(discipline ⑥)。

## 3. 知识层巡检

项目知识只放在 AGENTS 文档路由列出的位置。逐条看：

- **手册**：条目是否仍成立、是否已被代码、测试、项目文档或 ADR 更好地承载、是否只对一次性情形有用。AGENTS「手册」一节与实际文件一致。
- **协作约定**：AGENTS「协作约定」每条一句、彼此不重复、仍是用户的要求。
- **agent 私有记忆**：你运行的 agent 若有项目级私有记忆(如 Claude Code 的项目记忆目录)，逐条给出处理——属于同类任务做法的提升进手册，属于用户要求的提升进协作约定，属于项目事实的补进项目文档，进度、过期或重复的删除。提升后从私有记忆中删掉，私有记忆的索引同步更新。

## 4. TODO

逐条读懂它在说什么，再对照实况判断：做完了吗、还被什么卡着、对用户还重要吗。每条给出一种处理：

- **删除**：有落地证据的完成项直接删；没完成但已不重要的进确认清单。
- **压缩**：按 AGENTS 里 TODO 的格式改写，进确认清单时附改写后的文本。进展、计数和历史删掉，需要保留的细节挪进项目文档或归档，TODO 留指针。
- **保留**：已经符合格式且仍重要。

## 5. 全仓巡检

先用 `git ls-files` 加 `.workflow/` 列出范围内的文件清单，按目录过一遍；深读集中在近期归档涉及的改动和扫出信号的地方。范围大时按目录分批，汇报写明覆盖范围。

1. **近期落地核验**：归档里改动、新增、删除的模块与契约，逐项对照代码确认落地；相关文档跟上了没有。
2. **文档与实况**：README、docs、AGENTS、architecture、手册中的命令、路径、文件名、配置名、常量和接口描述，用 grep、`ls`、`--help` 或读代码核对仍然成立；`ADR-NNNN` 引用指向存在的文件。
3. **死物**：没有消费者的脚本、测试、配置、数据和文档(grep 引用与 import 确认)；只为一次性迁移存在的兼容层；残留的临时文件与空目录。
4. **重复与疤痕**：同一事实散在多处，收归一处并让其他处引用；防御性括注、事故叙述按 discipline ⑥ 蒸馏成正面表述。
5. **architecture**：只装当前设计现状(模块边界、数据模型、关键不变量、对外契约、已能用的功能)，具体决定引用 `ADR-NNNN`；进度看板、重定向空壳、逐字复述 ADR 的段落进确认清单。
6. **ADR 信号**：同一主题多份 ADR、ADR 之间或与代码说法冲突、一份 ADR 末尾追加了修订段(几代说法叠在一起)，列进汇报并建议 `/holistic`；本技能不改 ADR 正文。

处置时守住四条：

1. 带 `NO-GO`、`别翻案`、`已验证净负`、`留档不删`、`别重做` 标记的内容一律保留。
2. 可复跑的实验脚本连同结论随其 ADR 存续；ADR 删除或整体过时时，连同结论进确认清单。
3. 删除被 import 或被引用的文件前先 grep 全部引用方，连同引用方一起进清单。
4. 蒸馏只压表达：数据形状、硬上限、判据措辞照抄；带 `ADR-NNNN` 锚点的说法保留。吃不准是否承重就进确认清单。

## 6. Scratch 与旧归档

- **会话目录** `PL-`/`BS-`/`HO-`/`CH-<UUID>/`：UUID 已出现在 `_archive/` 中且内容不再被引用的，直接删除；没有对应归档的列入确认清单。仍被引用的材料搬到它该在的家，或进确认清单。
- **`runs/`**：带 `.done` 的按时间保留最近 10 个，其余删除；仍被任务或证据引用的另行保留；失败或中断(无 `.done`)的进确认清单。
- **其余产物**：说明内容与引用情况后进确认清单。
- **旧归档**：决定已进 ADR 或代码、未完成项已进 TODO 或已做完、也没有别处引用的归档，列入确认清单；最近几轮和仍在进行的工作保留。
- 删除使用核实过的精确路径，保留软链目标。

## 7. 汇报

自检：

- 近期碰过的常量、配置名、路径，文档说法与代码一致？
- 每类事实各归其家，同一事实只在一处？
- 确认清单里的事项只执行了用户勾选的，ADR 正文未改动？
- AGENTS「手册」一节与实际文件一致，`.last-cleaning` 已更新？

汇报：处理的归档范围；巡检覆盖范围(扫过的目录，未扫部分及原因)；已直接做的改动；确认清单(手册、知识层、TODO、文件与归档，分组列出)；交给 planner / bs 的事项，及是否建议 `/holistic`。用户勾选后执行，再报告执行结果。
